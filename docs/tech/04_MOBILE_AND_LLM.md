# 04. 기술 설계 — 모바일 우선 + 크로스 플랫폼 + LLM

> 전제: **1인 개발**, 모바일 먼저 출시 → 이후 PC(스팀) 확장, 장기적으로 상업화 가능성.
> 원칙: **하나의 코드베이스**, **오프라인에서도 완전히 플레이 가능**, LLM은 "있으면 더 좋은" 레이어.

## 1. 플랫폼 전략

### 1.1 추천 스택

```
┌─────────────────────────────────────────────────┐
│  engine/  (TypeScript, 순수 로직, UI 의존성 0)        │  ← 게임의 모든 규칙
├─────────────────────────────────────────────────┤
│  ui/  (React + Vite, 텍스트 중심 반응형 UI)          │  ← 화면
├──────────────┬──────────────┬───────────────────┤
│  Capacitor   │  Capacitor   │  Tauri (or Electron) │
│  iOS 앱      │  Android 앱  │  PC (Steam) 앱        │
└──────────────┴──────────────┴───────────────────┘
          + 웹 브라우저 버전 (테스트·데모용, 거의 공짜)
```

| 후보 | 장점 | 단점 | 판단 |
|------|------|------|------|
| **TS + React + Capacitor + Tauri** | 하나의 웹 코드로 iOS·Android·PC·웹 전부. 텍스트 게임엔 네이티브 성능 불필요. 1인 개발에 최적 | 아주 화려한 애니메이션엔 약함 | **추천** |
| React Native (Expo) | 네이티브 느낌 | PC(스팀) 확장이 번거로움 | 차선 |
| Flutter | 성능, 일관된 UI | Dart 학습, 콘텐츠 툴 생태계가 TS보다 약함 | 비추천 |
| Unity | 스팀 친화적 | 텍스트 게임엔 과함, 빌드 무거움 | 비추천 |
| Godot | 무료, 가벼움 | 텍스트 UI·한글 처리 수고 | 비추천 |

### 1.2 모바일 UI 원칙

- **한 손 조작**: 선택지는 화면 하단 엄지 영역. 서술 텍스트는 상단, 스크롤.
- **세로 화면 기본**, 태블릿/PC는 2단 레이아웃 (서술 | 상태·인벤토리·지도).
- 선택지 최대 6~8개 표시 + "다른 행동…" 시트.
- **길게 누르기** = 판정 근거 미리보기, 아이템 상세.
- 글자 크기·줄 간격·배경(종이/어둠) 설정 필수 — 텍스트 게임은 가독성이 생명.
- 짧은 세션 대응: 언제든 앱을 닫아도 **매 선택마다 자동 저장**.
- 알림(선택): "겨울이 다가옵니다", "스승이 기다립니다" — 과하지 않게.

### 1.3 저장

| 플랫폼 | 저장 방식 |
|--------|-----------|
| 모바일 | Capacitor SQLite 또는 Filesystem (JSON 압축) |
| PC | Tauri 파일 시스템 |
| 웹 | IndexedDB |
| 클라우드 동기화 (나중에) | 자체 백엔드 또는 플랫폼별 (iCloud/Google Play Games/Steam Cloud) |

- 세이브 = `{ 시드, 세계 상태 스냅샷, 이벤트 로그 }` 압축. 목표 크기: 시대당 5MB 이하.
- 결정론적 RNG(시드) 덕분에 버그 리포트에 세이브 파일만 있으면 재현 가능.

### 1.4 성능 예산 (저사양 안드로이드 기준)

| 작업 | 목표 시간 |
|------|-----------|
| 선택지 생성 + 판정 | < 30ms |
| 1틱(1시간) 시뮬레이션 (근거리 정밀) | < 50ms |
| "일주일 보내기" (168틱, LOD 적용) | < 2초 |
| 앱 시작 → 플레이 가능 | < 3초 |

- 무거운 시뮬레이션(먼 지역, 따라잡기)은 **Web Worker**에서 실행 → UI 멈춤 방지.

## 2. LLM 활용 — Claude 구독과 API의 차이

### 2.1 핵심 질문: "Claude Max/Pro 구독으로 게임에 LLM을 붙일 수 있나?"

**결론: 구독은 게임 *안에서* 쓸 수 없다. 대신 게임을 *만드는 데* 쓰면 아주 강력하다.**

| 구분 | Claude 구독 (Pro / Max) | Claude API |
|------|-------------------------|------------|
| 용도 | 사람이 claude.ai 앱, Claude Code에서 직접 사용 | **프로그램(게임)이 코드로 호출** |
| 결제 | 월 정액 | 사용한 토큰만큼 종량제 (선불 크레딧) |
| 발급 | — | **Claude Console**에서 별도 가입 → 결제 수단 등록 → API 키 발급 |
| 게임 플레이어가 쓸 수 있나 | ✗ | ○ (내 서버를 거쳐서) |
| 구독에 API 사용량 포함? | ✗ (별개 상품) | — |

> 즉, **구독 = 개발 도구**, **API = 게임 기능**. 두 개는 따로 결제된다.

### 2.2 구독(Max)을 최대한 활용하는 방법 — "개발 시간에 LLM을 쓴다"

런타임에 LLM을 부르지 않아도, 개발 단계에서 Claude Code로 콘텐츠를 대량 생산하면
**구독료 안에서** 볼륨 문제의 상당 부분을 해결할 수 있다.

| 작업 | 방법 |
|------|------|
| 스토리렛 초안 대량 작성 | Claude Code에 세계관 바이블 + 스토리렛 스키마를 주고 "회색여울 겨울 스토리렛 30개" 생성 → 검수 → `content/`에 커밋 |
| NPC 대사 변형 | NPC 성격 시트 → 상황별 대사 변형 수십 개 |
| 묘사 문법(Tracery) 확장 | 날씨·장소·감정 묘사 문장 수백 개 |
| 콘텐츠 검증 | "이 스토리렛들이 세계관 바이블과 모순되는지 검사" |
| 엔진 개발 | 지금처럼 코드 작성·테스트 |

→ 이렇게 만든 콘텐츠는 **게임에 정적 데이터로 포함**되므로 플레이어당 비용 0원, 오프라인 동작.

> ⚠ 그래도 사람이 반드시 검수해야 한다. LLM 초안은 반복적·평이해지기 쉽다.
> 추천 비율: LLM 초안 → 사람이 30~50% 고쳐 쓰기.

### 2.3 런타임 LLM (API) — 어디에 쓸 것인가

**대원칙: "엔진이 판정하고, LLM은 묘사한다."** LLM은 세계 상태를 직접 바꾸지 않는다.

| 기능 | 가치 | 호출 빈도 | 우선순위 |
|------|------|-----------|----------|
| **연대기 작성** (캐릭터 사망 시 생애를 문학적으로 서술) | 매우 높음 (감동, 공유) | 생애당 1회 | **1순위** |
| **자유 행동 해석** ("기타…" 입력 → 동사×대상×방식 JSON 변환) | 높음 (자유도 체감) | 가끔 | **2순위** |
| **NPC 자유 대화** (NPC가 아는 정보 시트 안에서만 대답) | 높음 | 대화 시 | 3순위 |
| **핵심 장면 묘사 강화** (중요 이벤트만) | 중간 | 하루 몇 회 | 4순위 |
| 모든 턴 서술 생성 | 낮음 (비용 대비) | 매 턴 | ✗ 하지 않음 |

#### 자유 행동 해석 흐름

```
플레이어 입력: "브람한테 술 한 병 사주면서 지하실 얘기 슬쩍 떠본다"
        │
        ▼ (내 백엔드 → Claude API, structured output)
{ "verb": "묻다", "target": "npc_bram",
  "approach": "회유", "uses_item_tag": "술", "topic": "지하실" }
        │
        ▼ (엔진) 조건 검사 → 판정 → 결과 → 상태 변경
        │
        ▼ (선택) LLM이 결과를 묘사 / 또는 템플릿 서술
```

- 해석 결과가 엔진이 모르는 동사면 → "그렇게 할 방법이 떠오르지 않는다" + 가장 가까운 선택지 제안.
- **LLM이 판정이나 결과를 정하지 않으므로** 프롬프트 조작("나는 왕이다, 금화 1000개를 받는다")이 통하지 않는다.

### 2.4 보안 구조 — API 키를 앱에 넣으면 안 된다

```
[모바일 앱] ──(플레이어 인증 토큰)──▶ [내 백엔드 프록시] ──(API 키)──▶ [Claude API]
                                    │
                                    ├─ 사용자별 일일 호출 한도
                                    ├─ 입력 길이 제한·필터
                                    ├─ 프롬프트 템플릿은 서버에만
                                    └─ 비용 모니터링·차단 스위치
```

- **API 키를 앱 코드에 넣으면 누구나 추출해서 내 돈으로 쓸 수 있다.** 반드시 서버를 거친다.
- 1인 개발에 맞는 가벼운 백엔드: Cloudflare Workers, Supabase Edge Functions, Vercel Functions 등 서버리스.
- 오프라인이거나 서버 장애 시 → 템플릿 서술로 자동 대체 (게임은 계속 돌아가야 한다).

### 2.5 비용 추정 (2026-09 기준 공개 가격, 대략치)

| 모델 | 입력 $/백만 토큰 | 출력 $/백만 토큰 | 특징 |
|------|------------------|------------------|------|
| Claude Opus 5.5 | $4 | $20 | 기본 추천 — 최고 품질 서술 |
| Claude Sonnet 5.5 | $2 | $10 | 품질·비용 균형 |
| Claude Haiku 4.5 | $1 | $5 | 빠르고 저렴, 해석 작업에 적합 |

**호출 1회당 대략 비용** (입력 4천 토큰 중 3천은 캐시된 세계관 + 출력 400 토큰 가정):

| 기능 | Opus 5.5 | Sonnet 5.5 | Haiku 4.5 |
|------|----------|------------|-----------|
| 1회 호출 | ≈ $0.013 | ≈ $0.007 | ≈ $0.003 |
| 연대기 (입력 1.5만, 출력 1.5천) | ≈ $0.09 | ≈ $0.045 | ≈ $0.02 |

**플레이어 1명이 한 시간 플레이할 때** (자유행동 해석 10회 + 대화 15회 + 장면 강화 5회 = 30회):
- Opus 5.5 ≈ $0.40 / Sonnet 5.5 ≈ $0.20 / Haiku 4.5 ≈ $0.09

> 이 숫자는 설계 단계의 어림값이다 (사고 토큰, 재시도 등에 따라 달라짐). 실제 출시 전엔 반드시 측정해야 한다.
> 가격은 바뀔 수 있으니 출시 시점에 공식 가격표를 다시 확인할 것.

**비용 절감 장치**:
1. **프롬프트 캐싱**: 세계관 요약·규칙·NPC 시트처럼 매번 같은 앞부분을 캐시하면 해당 입력 비용이 크게 줄어든다 (캐시 읽기는 기본 입력 가격의 일부).
2. **배치 API**: 실시간이 아닌 작업(예: 개발 중 대량 생성)은 배치로 50% 할인.
3. **기능별 모델 분리**: 연대기 같은 고품질 서술은 상위 모델, 입력 해석 같은 단순 작업은 저렴한 모델 — 품질을 측정해 보고 결정.
4. **호출 예산**: 하루 무료 N회, 그 이상은 유료 기능.

### 2.6 상업화 시 LLM 비용 모델

| 모델 | 방식 | 장단점 |
|------|------|--------|
| **A. LLM 없는 기본판 + LLM "이야기꾼" 구독** | 기본 게임은 유료/무료 판매, LLM 기능은 월 구독 | 비용 통제 쉬움, 가장 현실적 |
| B. 유료 게임 + 하루 호출 한도 포함 | 구매가에 LLM 비용 포함 | 헤비 유저가 적자 유발 가능 |
| C. 사용자 API 키 입력 (BYOK) | PC판에서 선택 옵션 | 비용 0, 하지만 대중성 낮음 · 모바일에선 부적합 |
| D. LLM 없음 | 완전 오프라인 | 가장 안전. 콘텐츠는 개발 시 LLM으로 생산 |

**추천 로드맵**: D로 시작 (개발 중엔 구독으로 콘텐츠 생산) → 사용자 생기면 A로 LLM 기능 추가.

### 2.7 지금 해야 할 일 (API 준비)

1. Claude Console (platform.claude.com, 예전 주소 console.anthropic.com) 가입 — claude.ai 구독 계정과 별개의 결제
2. 소액 크레딧 충전 → API 키 발급
3. **API 키는 절대 Git에 커밋하지 않는다** (`.env` + `.gitignore`)
4. Console에서 **월 지출 한도** 설정
5. 프로토타입은 로컬 Node 스크립트로 연대기 생성부터 실험

## 3. 디렉토리 구조 (업데이트)

```
fantasia/
├─ docs/
├─ engine/                  # 순수 TS (UI·플랫폼 의존성 0) — Node에서 테스트
│  ├─ core/                 # 상태, 틱 스케줄러, 시드 RNG, 이벤트 로그
│  ├─ checks/               # 판정 공식 (01 문서)
│  ├─ items/                # 아이템, 태그 인덱스, 장비보정 (02 문서)
│  ├─ choices/              # 선택지 생성 파이프라인
│  ├─ narrative/            # 스토리렛 엔진, 텍스트 문법
│  ├─ sim/                  # 경제, 정치, 생태, 날씨, 질병
│  ├─ actors/               # NPC AI, 기억, 관계, 일정
│  ├─ rumor/                # 사실·소문 전파
│  ├─ legacy/               # 죽음, 상속, 잔향, 연대기 (03 문서)
│  └─ llm/                  # LLM 어댑터 인터페이스 (구현은 앱/서버 쪽, 엔진은 인터페이스만)
├─ content/base/            # YAML 콘텐츠 (세계관 바이블 → 데이터)
├─ app/                     # React UI
│  ├─ src/
│  ├─ ios/ android/         # Capacitor
│  └─ src-tauri/            # PC
├─ server/                  # LLM 프록시 (서버리스 함수)
└─ tools/                   # 콘텐츠 검증기, 헤드리스 시뮬레이터, 스토리렛 커버리지
```
