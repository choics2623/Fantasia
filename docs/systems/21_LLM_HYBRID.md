# 21. LLM 하이브리드 — LLM은 제안하고, 규칙이 판정한다

> 선택지 문장, NPC 대화, 캐릭터 메모리, 소문은 **LLM이** 만든다.
> 가능한 행동, 성공 확률, 결과, 수치, 세계 상태는 **규칙 엔진이** 쥔다.
> **LLM은 필수다.** 연결이 없거나 LLM이 응답하지 않으면 게임을 진행하지 않는다 — 문장 결이 다른 대체 문장으로 몰래 이어 가지 않는다.
> (결정 2026-10: 사용자. 그 전의 "LLM 없이도 완성" 원칙은 폐기)

관련 문서: 01 판정 · 02 아이템과 선택지 · 05 대사 DB · 08 NPC·사실 · 10 평판 · 16 메아리 · 18 연출가 · tech/04 기술·비용

## 1. 원칙

| 원칙 | 뜻 | 왜 |
|------|----|----|
| **제안과 판정의 분리** | LLM 출력은 언제나 "제안"이다. 엔진이 검증해서 받아들이거나 버린다 | 프롬프트 조작("나는 왕이다")이 통하지 않는다. 규칙이 깨지지 않는다 |
| **아는 것만 보낸다** | NPC 대화 프롬프트에는 그 NPC가 **아는 사실만** 넣는다 (08 `known_by`) | 비밀이 새는 것을 프롬프트 지시가 아니라 **구조로** 막는다 |
| **숫자는 엔진의 것** | LLM은 확률·수치를 쓰지 않는다. 쓰더라도 정해진 태그로만 쓰고, 엔진이 태그를 상한이 있는 보정값으로 바꾼다 | 수치가 출렁이지 않는다. 밸런스를 잡을 수 있다 |
| **시드가 사건을 정한다** | 무엇이 일어나는지는 회차 시드와 규칙이 정한다. LLM은 그것을 **어떻게 말할지**만 바꾼다 | 회귀 설계(03의 고정·흐름·표류)가 유지된다. 같은 저녁이 매번 **다르게 들리지만 같은 일이 일어난다** |
| **LLM 필수, 상태는 원자적으로** | LLM이 없으면 플레이하지 않는다. 한 턴은 "판정 + 서술"이 함께 성공해야 확정된다. 서술이 실패하면 판정도 되돌린다 | 문장의 결이 한 게임 안에서 섞이지 않는다. 실패가 세계 상태를 반쯤 바꿔 놓지 않는다 |
| **톤은 정본을 따른다** | 그림다크, 설교 없음, WORLD_BIBLE §0.3의 두 줄 | 세계관 일관성 |

## 2. 역할 분담표

| 영역 | LLM | 규칙 엔진 | 작가가 미리 쓴 것 (05) |
|------|-----|-----------|-------------------------|
| **선택지 문장** | 행동 후보마다 장면에 맞는 문장 | 행동 후보(어포던스) 생성, 확률, 결과 | ◈ 기억 선택지·스토리렛 선택지는 작가 문장 그대로 |
| **결과 서술** | 판정 결과(5단계)를 장면 문장으로 | 결과 등급, 상태 변화 | 핵심 장면(첫 죽음, 회귀, 재회)의 고정 박자 |
| **NPC 대화** | 그 인물의 말투로 대사, 플레이어 자유 입력 이해 | NPC가 아는 사실, 감정, 관계 수치, 대화 판정 | NPC별 **말투 견본** — 프롬프트에 넣는 예시 대사 |
| **캐릭터 메모리** | 대화·장면에서 기억 후보를 JSON으로 추출 | 검증, 상한, 저장, 퇴색, 회귀 초기화 (중요한 기억은 규칙이 직접 남긴다) | — |
| **평판·소문** | 소문 문장과 왜곡된 판본 | 사건 크기, 목격자, 전파 범위·속도, 평판 수치 | 왜곡 종류별 소문 견본 |
| **자유 행동 입력** | 문장을 행동 문법으로 해석 | 해석된 행동의 조건 검사와 판정 | 입력 불가 (선택지만) |
| **회차 기록·연대기** | 문학적 서술 | 무엇이 기록될지 (03 `LoopRecord`) | 템플릿 연대기 |

## 3. 한 턴의 흐름

```
① 엔진: 세계 상태 + 장면 → 행동 후보(어포던스) 6~12개 + 스토리렛 선택지 + ◈ 기억 선택지
② LLM : 후보 중 3~5개를 골라 문장을 쓴다 (+ 선택적으로 "창의적 해석" 1개)
③ 엔진: 검증 → 확률 계산(01) → 체감 확률 표시(01 §4)
④ 플레이어: 고른다 (또는 자유 입력 → LLM 해석 → ③으로)
⑤ 엔진: 판정 → 결과 등급 → 상태 변화 → 사건(Event) 발행
⑥ LLM : 결과를 박자 단위로 서술 (19의 박자 길이·상태 필터를 지킨다)
⑦ 엔진: 사건 → 사실·목격자 → 메모리 후보 / 소문 / 평판 / 메아리(16)
⑧ (하루 끝) LLM: 메모리 정리·퇴색 요약 — 몰아서 한 번에
```

- ②와 ⑥은 한 번의 호출로 묶을 수 있다 (다음 선택지 문장 + 이번 결과 서술).
- ◈ 기억 선택지(14)와 스토리렛 선택지는 **작가가 쓴 문장을 그대로** 쓴다. LLM은 어포던스 선택지만 쓴다. 핵심 장면의 손맛을 지키기 위해서다.

## 4. 선택지 생성

### 4.1 어포던스 — 엔진이 만드는 행동 후보

02 문서의 태그 기반 선택지 생성을 그대로 쓴다. 엔진은 문장 대신 **행동 구조**를 만든다.

```ts
interface Affordance {
  id: string;                     // 'aff_intimidate_bram_knife'
  verb: VerbId;                   // 위협하다, 설득하다, 속이다, 훔치다, 숨다, 주다, 묻다, 떠나다 …
  target?: NpcId | ObjectId;
  skill: SkillId;                 // 판정 스킬 (01)
  item?: ItemId;                  // 쓰는 아이템 (02)
  knowledge?: FactId;             // 근거로 쓰는 사실 (01 §3.1 논거보정)
  risk: 'none' | 'low' | 'mid' | 'high' | 'lethal';
  odds: number;                   // 엔진이 계산한 P (LLM에는 보내지 않는다 — §4.3)
  tags: string[];                 // 'violent', 'quiet', 'honest', 'cruel' … (성향·목소리 반응용)
}
```

### 4.2 LLM에 보내는 것과 받는 것

**보내는 것** (캐시되는 앞부분 → 바뀌는 뒷부분 순서, §9.2)
1. 고정: 문체 규칙(2인칭, 박자 250자, 그림다크, 설교 금지), 출력 스키마
2. 지역: 장소 묘사 시트, 등장 NPC 카드(§5.1)
3. 장면: 지금 상황 요약, 플레이어 상태(허기·통증·공포 — 19 필터가 문장에 묻어나도록), 최근 박자 3개
4. 어포던스 목록 (확률 대신 **위험 등급만**)

**받는 것** — 구조화 출력(structured outputs)으로 스키마를 강제한다.

```json
{
  "choices": [
    { "affordance": "aff_intimidate_bram_knife",
      "text": "단검 손잡이를 탁자에 올려놓고, 아무 말 없이 브람을 본다" },
    { "affordance": "aff_ask_bram_cellar_drink",
      "text": "술 한 잔을 밀어 주며, 요즘 지하실 쥐가 많지 않으냐고 묻는다" },
    { "affordance": "aff_leave",
      "text": "그릇을 내려놓고 빗속으로 나간다" }
  ],
  "creative": { "intent": "브람의 딸 이야기를 꺼내 동정을 산다",
                "closest_affordance": "aff_persuade_bram", "argument_tags": ["family"] }
}
```

### 4.3 검증 규칙
- `affordance`가 목록에 없으면 그 선택지를 버린다. 3개 미만이 남으면 템플릿으로 채운다.
- 문장에 **목록에 없는 아이템·인물·장소**가 나오면 버린다 (사전 대조).
- 문장이 행동과 다른 짓을 묘사하면(위협 행동인데 "칼로 찌른다") 버린다 — 동사 분류기(소형 모델 또는 규칙).
- LLM에 확률을 보내지 않는 이유: 문장이 확률을 흘리지 않게 하기 위해서다("확실히 통할 것 같은…"). 확률은 엔진이 체감 등급(01 §4.1)으로 따로 붙인다.
- **창의적 해석**은 엔진이 `closest_affordance`로 판정한다. `argument_tags`는 §7의 화이트리스트 보정으로만 반영된다.

### 4.4 언제나 들어가는 선택지
- 떠나기 / 침묵하기 — 아무것도 하지 않을 자유 (그림다크에서 가장 자주 옳은 선택).
- 플레이어가 고른 적 있는 행동 유형의 변주 — 플레이 스타일을 존중한다.
- 성향과 반대되는 선택지 하나 — 15 문서의 목소리가 걸고넘어질 거리를 만든다.

### 4.5 회귀와 문장
- 사건은 같고 문장은 바뀐다. 그래서 같은 저녁이 매번 다르게 들린다 (18의 신선도 규칙과 같은 방향).
- 단, **회차 안에서 다시 불러오면 같은 문장**이 나와야 한다 → 생성 결과를 `(loopSeed, sceneId, beat, stateHash)`로 저장한다.
- 지난 회차에 고른 선택지는 기억 잉크 ┊(14)로 표시한다. 그 문장은 지난 회차에 실제로 보인 문장을 그대로 꺼낸다.

## 5. NPC 대화

### 5.1 NPC 카드 — 프롬프트에 들어가는 그 사람

```yaml
npc: npc_bram
name: 브람
voice: "말이 짧다. 존댓말을 쓰지 않는다. 대답 대신 그릇을 닦는다. 욕은 '빌어먹을' 하나만 쓴다."
temperament: [과묵, 의심, 다정함을 숨김]
goals: ["지하실의 에길 일가를 겨울까지 숨긴다", "배급 장부의 구멍을 들키지 않는다"]
fears: ["볼크의 개", "마르타의 장부"]
mood: { fear: 2, anger: 0, warmth: 1 }          # 엔진이 매 장면 갱신
toward_player: "처음 보는 얼굴. 경계한다."        # 08 관계 수치를 말로 바꾼 것 (숫자는 보내지 않는다)
knows:                                           # 08 known_by에서 이 사람 몫만
  - fact_egil_family_in_cellar
  - fact_hagen_drinks_with_volk
does_not_know_but_suspects:
  - "하겐이 탈주자를 판다는 소문"
memories: [ … §6에서 고른 상위 8개 … ]
hard_rules: ["에길 이야기를 먼저 꺼내지 않는다", "모르는 것은 모른다고 한다"]
```

- **카드에 없는 비밀은 LLM이 알 수 없다.** "비밀을 말하지 마"라고 지시하는 대신, 비밀을 아예 보내지 않는다.
- 숫자 대신 말로 보낸다 (호감 +35 → "조금 마음을 열었다"). LLM이 숫자를 흉내 내지 않게 한다.

### 5.2 대화 한 번의 흐름
1. 플레이어는 **선택지**(§4)로 말하거나, **자유 입력**으로 말한다.
2. 말에 판정이 걸리는 경우(설득·거짓말·위협·캐묻기)는 엔진이 먼저 판정한다 (01 §3). LLM은 결과 등급을 받아 그 등급에 맞는 반응을 쓴다. **판정 없이 LLM이 마음대로 넘어가 주는 일은 없다.**
3. NPC가 비밀을 말하는 것은 언제나 엔진의 결정이다: 판정 성공, 관계 문턱, 스토리렛 조건. 그때 엔진이 해당 사실을 그 장면의 카드에 **풀어서** 넣는다.
4. 대화 길이는 NPC 등급과 기분이 정한다 (S 무제한 · A 8번 · B 4번 · C 2번 주고받기). 길어지면 NPC가 대화를 끝낸다 — "그만 가라."

### 5.3 거짓말과 주장
- 플레이어가 한 말은 사실이 아니라 **주장(claim)** 으로 저장된다.
- 진위는 엔진이 안다 (사실 DB와 대조). NPC가 믿는지는 기만 vs 통찰 판정(01 §2.4)으로 정한다.
- 믿은 거짓말은 NPC 안에서 사실처럼 작동하다가, 반대 증거를 만나면 **배신감**(신뢰 큰 폭 하락)으로 바뀐다.

## 6. 캐릭터 메모리

### 6.1 무엇을 기억하나

| 종류 `kind` | 예 | 엔진 처리 |
|-------------|----|-----------|
| `fact_learned` | 브람은 하겐이 볼크와 술을 마신다는 걸 알게 됐다 | 08 `known_by`에 추가 → 소문 전파 대상 |
| `claim` | 셋째가 "에길의 외삼촌을 안다"고 말했다 | 진위는 엔진, 믿음은 판정 |
| `impression` | 브람은 셋째를 영리하다고 보기 시작했다 | 인상 태그 ±값 (상한 §6.3) |
| `emotion` | 브람은 셋째에게 겁을 먹었다 | 감정 축 갱신, 며칠에 걸쳐 흐려짐 |
| `promise` | 셋째는 사흘 안에 약을 구해 오겠다고 했다 | 기한 달린 기대. 어기면 신뢰 하락 (16 맹세와 다른 가벼운 약속) |
| `debt` | 브람은 셋째에게 빚을 졌다 (빵을 나눠 받음) | 호의 저장 — 나중에 한 번 꺼내 쓸 수 있다 |
| `threat` | 셋째가 지하실 일을 알고 있다고 은근히 겁줬다 | 두려움 + 원한 씨앗. 17 숙적 후보 조건에 들어간다 |
| `suspicion` | 셋째가 아직 일어나지 않은 일을 안다 | 잔향 징후 노출 판정에 더해진다 (RACES 징후) |

인상 태그 예: 영리함, 위험함, 정직함, 거짓말쟁이, 다정함, 비굴함, 용감함, 이상함(잔향), 쓸모 있음, 짐.

### 6.2 추출 — LLM이 뽑고 엔진이 거른다

대화나 장면이 끝나면 LLM이 기억 후보를 뽑는다.

```json
{ "memories": [
  { "npc": "npc_bram", "kind": "impression", "about": "player", "tag": "영리함", "delta": 4,
    "evidence": "지하실 쥐가 많지 않으냐고 돌려서 물었다", "salience": 3 },
  { "npc": "npc_bram", "kind": "suspicion", "about": "player",
    "evidence": "에길의 이름을 먼저 말했다 — 아무도 그 이름을 모른다", "salience": 5 }
]}
```

**검증**
1. `npc`는 그 장면에 있었던 인물이어야 한다. 그 자리에 없던 사람은 기억할 수 없다.
2. `evidence`는 실제 대화 기록에서 확인된다 (문장 대조). 근거 없는 기억은 버린다.
3. `fact_learned`는 실제 사실 ID에 연결돼야 한다. 연결이 안 되면 `claim`으로 낮춘다.
4. 수치 상한(§6.3)을 넘으면 깎는다.
5. 엔진이 이미 아는 사건(⑤에서 발행된 Event)은 LLM 없이도 기억을 만든다 — **중요한 기억은 규칙이 보장하고, LLM은 미묘한 것을 더한다.**

### 6.3 상한 — 한 번의 대화가 사람을 바꾸지 않는다

| 항목 | 대화 한 번 | 하루 |
|------|-----------|------|
| 인상 태그 하나 | ±5 | ±10 |
| 호감 (08) | ±8 | ±15 |
| 신뢰 (08) | ±6 | ±12 |
| 큰 사건(목숨을 구함, 배신, 폭력) | 상한 없음 — **엔진 사건으로만** | — |

### 6.4 저장·퇴색·정리

| NPC 등급 (08) | 기억 슬롯 | 퇴색 |
|---------------|-----------|------|
| S | 60 | 느림 |
| A | 30 | 보통 |
| B | 12 | 빠름 |
| C | 4 (승격 전까지) | 매우 빠름 |

- 기억마다 `salience`(1~5)와 마지막으로 떠올린 날을 둔다. 슬롯이 차면 중요도 × 최근도가 낮은 것부터 **요약**된다 ("셋째와 몇 번 말을 섞었다 — 이상한 아이").
- 정리는 **하루 끝 장면**(18)에서 몰아서 한다 (실시간이 아니므로 배치 처리, §9.3).
- 프롬프트에는 상위 8개만 넣는다 (현재 대화 주제와 관련 있는 것 우선).

### 6.5 회귀
- 회귀하면 **모든 NPC 메모리는 회귀점 상태로 돌아간다** (03). 브람은 다시 셋째를 모른다.
- 플레이어 쪽에는 남는다: 인물 수첩(08 §5)의 관찰 기록, 지난 회차 관계 ◇ (20).
- 지난 회차에 브람이 품었던 인상은 수첩에 "지난 회차의 브람은 나를 영리하다고 여겼다"로 남는다 — 이번 회차의 브람에게는 없는 기억이다. 그 간극이 20 문서의 「나를 처음 보는 사람」을 만든다.

### 6.6 플레이어에게 보이는 것
- 통찰 판정에 성공하거나 관계가 깊으면 인물 수첩에 한 줄이 드러난다: 「브람은 당신을 경계하면서도, 영리하다고 여기기 시작했다.」
- 수치는 보이지 않는다. 문장으로만.
- `suspicion` 기억은 특별 표시 없이 행동으로만 드러난다 (브람이 당신을 오래 본다) — 잔향 징후는 숨겨져야 무섭다.

## 7. 판정과의 연결 — LLM은 확률을 만지지 않는다

성공 확률은 01 문서의 공식이 정한다: 캐릭터(스킬·능력치·재능·몸의 상한), 상황(장소·시간·날씨·준비), 대상(상대의 저항 점수·관계·기분), 난이도, 장비, 아는 정보.

LLM이 판정에 영향을 주는 길은 **하나뿐**이다: 논거 태그.

| 태그 | 조건 (엔진이 확인) | 보정 |
|------|-------------------|------|
| `uses_fact:<id>` | 플레이어가 그 사실을 실제로 알고 있다 | 01 §3.1 논거보정 +5~+20 (사실의 무게별) |
| `appeals_interest:<goal>` | 그 목표가 NPC 카드의 `goals`에 있다 | 이해관계보정 +5~+15 |
| `appeals_fear:<fear>` | 그 두려움이 카드의 `fears`에 있다 | 위압 쪽 +5~+15, 원한 씨앗 |
| `offers_item:<id>` | 플레이어가 그 물건을 가졌다 | 02 아이템 보정 |
| `family` / `faith` / `pride` … | 카드의 `temperament`와 맞는다 | +3~+8 |

- 태그 합계 상한 +25. 근거 없는 태그(모르는 사실을 썼다고 주장)는 0 처리하고, 그 시도 자체를 `claim`으로 기록한다.
- 그래서 **말을 잘 고르면 확률이 오른다** — 정보를 모으고, 상대를 알고, 물건을 준비하는 01 문서의 재미가 자유 입력에서도 그대로 산다.

## 8. 평판과 소문 — 마을에서 국가까지

10 문서의 평판 수치에 **규모(scale)** 를 더한다.

### 8.1 사건의 크기와 목격

엔진이 사건마다 정한다.
- **크기 M (0~5)**: 0 사소함(빵을 훔침) · 1 동네 일 · 2 마을 사건(감독관 폭행) · 3 영지 사건(감독관 살해, 집단 탈주) · 4 지방 사건(영주 암살 시도) · 5 국가 사건(진룡의 상처, 대봉기)
- **목격**: 누가 봤나(NPC 목록), 몇 명이 봤나, 증거가 남았나(시체, 불탄 집, 문서)
- **신원 연결**: 얼굴을 봤나, 이름을 아나 (10 §3 정체)

### 8.2 전파

| 단계 | 범위 | 도달 조건 | 걸리는 시간 (기본) |
|------|------|-----------|-------------------|
| 마을 | 회색여울 | 목격자 1명 이상 | 반나절 |
| 영지 | 레이번 영지 | M ≥ 2 | 2~4일 |
| 지방 | 변경 지방 | M ≥ 3 | 1~2주 |
| 국가 | 용제국 | M ≥ 4 | 3~6주 |
| 대륙 | 여러 나라 | M = 5 | 두 달 이상 |

- 전파는 08 소문 시스템의 사람 사이 경로(상인·순례자·전령·노예 수레)를 따라간다. 경로가 막히면(폭설, 봉쇄) 늦어진다.
- 단계를 하나 넘을 때마다 **왜곡** 판정: 과장(숫자가 커진다) · 주체 바뀜(다른 사람이 한 일이 된다) · 동기 바뀜 · 신원 흐림(얼굴이 지워진다). 왜곡은 엔진이 고르고, LLM은 그 왜곡이 들어간 소문 문장을 쓴다.
- 평판 수치 변화는 단계마다 10 문서의 평가표 × 규모 계수(마을 1.0 · 영지 0.7 · 지방 0.5 · 국가 0.35 · 대륙 0.2)로 들어간다. 먼 곳일수록 약하지만 넓다.

### 8.3 예 — 즈닉을 죽였다 (M 3, 목격자 페인, 시체 발견)

| 날 | 어디 | 소문 (LLM 문장, 엔진 왜곡) | 평판 |
|----|------|---------------------------|------|
| 1일 밤 | 회색여울 | "누가 즈닉 목을 땄대. 배급 줄 애들 중 하나라던데." | 인간 +12, 목줄단 −15, 레이번가 −10 |
| 3일 | 레이번 영지 | "회색여울 농노 놈들이 감독관을 패 죽였다." (주체가 '농노들'로) | 용인 귀족 −5, 인간 농노 +6 |
| 2주 | 변경 지방 | "변경에서 인간 봉기 조짐. 감독관 셋이 죽었다." (과장) | 용제국 경계 단계 +1 (10 §5.1) |

> 수치와 단계는 전부 규칙이다. LLM은 엔진이 고른 왜곡을 문장으로만 쓴다.

## 9. 모델, 비용, 캐시

### 9.1 모델 배치

| 작업 | 모델 | 이유 |
|------|------|------|
| 선택지 문장 + 결과 서술 | Claude Haiku 4.5 | 빠르고 싸다. 구조화 출력 |
| 메모리 추출, 자유 입력 해석 | Claude Haiku 4.5 | 분류·추출 작업 |
| S등급 NPC 깊은 대화, 핵심 장면 | Claude Sonnet 5.5 | 말투와 감정의 결 |
| 회차 기록·시대 연대기 | Claude Sonnet 5.5 (품질 측정 후 결정) | 회차당 1회라 비용 부담이 작다 |
| 콘텐츠 대량 생산 (개발 중) | Haiku 4.5 / Sonnet 5.5, 핵심은 Opus 5.5 | 05 §7 |

- 어떤 작업에 어떤 모델이 충분한지는 **실제 플레이 로그로 측정해서** 정한다. 위 표는 출발점이다.

### 9.2 프롬프트 구조 — 캐시가 맞도록

```
[고정 — 캐시]    문체 규칙 · 출력 스키마 · 세계관 요약
[지역 — 캐시]    장소 시트 · 등장 NPC 카드
[장면 — 매번]    상황 요약 · 상태 · 최근 박자 · 어포던스
```
앞부분이 한 글자라도 바뀌면 캐시가 깨진다. 시간·날짜·난수처럼 매번 바뀌는 것은 반드시 맨 뒤에 둔다.

### 9.3 비용을 줄이는 장치
1. **공유 캐시**: 모든 플레이어가 지나는 장면(1일 저녁 배급 줄)의 문장은 서버가 `(sceneId, stateHash)`로 저장해 다음 플레이어에게 재사용한다. 상태가 같으면 다시 만들지 않는다. 변주가 필요하면 저장된 판본 몇 개 중에서 고른다.
2. **하루 끝 배치**: 메모리 정리·퇴색·소문 문장은 실시간이 아니다. 배치 처리(할인)로 돌린다.
3. **호출 묶기**: 결과 서술과 다음 선택지를 한 번에 만든다.
4. **예산**: 플레이어별 호출 한도(상업화 모델에 따라 하루/월). 한도에 가까워지면 미리 알리고, 넘으면 **하루의 끝 장면에서** 멈춘다 — 장면 한가운데서 끊지 않는다. 몰래 대체 문장으로 내려가지 않는다.
5. **선생성**: 플레이어가 선택지를 읽는 동안 가장 유력한 선택 1~2개의 결과 서술을 미리 만들어 둔다 (지연 체감 감소, 버려지는 호출 비용과 맞바꿈).

### 9.4 대략 비용 (설계 단계 어림값 — 출시 전에 반드시 측정)

한 턴: 입력 약 1.5천 토큰 (+ 캐시된 고정부), 출력 약 400 토큰.

| 모델 | 턴당 | 플레이 1시간 (60~100턴) |
|------|------|------------------------|
| Haiku 4.5 ($1 / $5 per 백만 토큰) | ≈ $0.004 | ≈ $0.3~0.5 |
| Sonnet 5.5 ($2 / $10) | ≈ $0.008 | ≈ $0.5~1 |

공유 캐시가 잘 맞으면 초반 장면은 거의 공짜가 된다. 비용은 플레이어가 세계를 멀리 벗어날수록(새로운 조합) 오른다. 상업화 모델은 tech/04 §2.6.

## 10. 실행 환경 — 구독과 API

| 단계 | 방법 | 비용 |
|------|------|------|
| **혼자 개발·테스트** | 로컬 개발 서버가 Claude Agent SDK 또는 `claude -p`(헤드리스 Claude Code)를 호출한다. 개발자 본인의 Claude 구독 로그인으로 돌아간다 | 구독 한도 안. 느리고(수 초) 한도가 있어 실험용 |
| **다른 사람이 플레이 (배포)** | 앱 → 내 백엔드 프록시(API 키 보관) → Claude API (tech/04 §2.4) | 종량제 |
| **PC판 선택 옵션** | 플레이어가 자기 API 키를 넣는다 (BYOK) | 플레이어 부담 |

- 구독은 본인 개인 사용 용도다. 구독 로그인으로 다른 사람에게 게임 기능을 제공하면 안 된다 (조건은 약관에서 확인).
- 그래서 엔진 코드는 **LLM 호출부를 한 인터페이스로 감싼다**: `LlmProvider = 'local-subscription' | 'server-api' | 'byok' | 'mock'`. 개발 중엔 구독으로, 출시 때는 서버로 바꿔 끼운다. `mock`은 엔진 자동 테스트 전용(고정 응답)이고 플레이어에게는 열리지 않는다.
- **연결이 없으면**: 시작 화면에서 막는다 ("잿빛 실이 끊겼다 — 연결을 확인하세요"). 플레이 중 끊기면 지금 박자에서 멈추고, 연결되면 같은 자리에서 다시 잇는다. 마지막으로 확정된 턴까지만 저장된다.

## 11. 품질과 안전

| 검사 | 방법 |
|------|------|
| 스키마 | 구조화 출력 + 엔진 재검증 |
| 사전 대조 | 아이템·인물·장소·사실 ID 화이트리스트 |
| 정보 누설 | 카드 밖 고유명사가 대사에 나오면 버린다 |
| 톤 | 설교 어휘 검출(15 문서의 검출 목록 재사용), 현대어·외래어 검출 |
| 한국어 | 조사 자동 보정(05 §5.1), 경어 체계 = 신분(05 §5.2) 검사 — 용인 귀족에게 반말하는 농노는 판정 결과로만 나온다 |
| 박자 | 250자 초과 시 자르지 않고 박자를 나눈다 (19) |
| 정본 | WORLD_BIBLE §0.3의 두 줄은 출력 필터와 프롬프트 양쪽에서 막는다 |
| 회귀 테스트 | 고정 시드·고정 상태의 장면 100개를 매 빌드마다 돌려, 검증 탈락률과 응답 시간을 잰다 |

실패하면: 1회 재생성 → 그래도 실패하면 **그 턴 전체를 되돌린다**(판정·상태 변화 취소) → "잠시 숨을 고른다" 화면과 다시 시도 버튼. 같은 판정을 다시 굴려 이득을 보지 않도록, 되돌린 턴의 난수는 보존해 재시도 때 그대로 쓴다.

3. 응답 시간 — 선택지가 2초 안에 나오는가? 아니라면 다음 선택지를 미리 만들어 두는 선생성이 필요하다.

| 회귀 장면이 산다 | 2회차에 에길 이야기를 먼저 꺼내자 LLM이 엔진 지시("섬뜩해한다")를 받아 브람이 "넌 왜 알아?"라고 묻는다. 엔진은 의심 기억(중요도 5)을 남긴다 | §6.1 `suspicion` — 규칙이 보장하고 LLM이 연기한다 |
| 실패 판정 뒤의 흘림 | 지하실 질문이 **실패**했는데 서술에 "빗소리 속에서 뭔가 움직이는 소리"가 붙었다 — 비밀은 말하지 않았지만 힌트가 샜다 | 결과 지시에 "실패면 힌트도 없다"를 명시하고, 실패 박자는 템플릿 비중을 높인다 (§4.3 검증에 '실패 박자의 비밀 관련 어휘' 검사 추가) |
| 2인칭 흔들림 | 첫 시도에서 서술이 주인공을 "셋째"라고 불렀다 | 문체 규칙에 "서술의 주인공은 언제나 '당신'"을 명시 → 해결 |
| 기억 추출 | 인상 2~3개, 근거 인용이 실제 대화와 맞아 검증을 통과. 인상 값은 ±2~4로 상한(±5) 안 | §6.2~6.3 그대로 |
| LLM 필수로 전환 | 실험 뒤 결정: LLM이 없으면 플레이하지 않는다. 실험 서버도 공급자 실패 시 턴을 되돌리고 다시 시도 화면을 띄운다 | §1, §10, §11 |
