# 08. NPC와 관계망 — 수백 명의 복잡한 관계를 정리하는 법

> 질문: "NPC가 엄청 많고 관계도 엄청 복잡할 텐데 이걸 어떻게 정리하나? 관계도?"
> 답: **관계도를 손으로 그리지 않는다.** 관계를 **데이터(그래프)** 로 적고, 관계도는 도구가 **자동으로 그린다.**
> 사람이 관리하는 것은 "누가 누구에게 무엇인가"라는 한 줄짜리 관계 기록뿐이다.

---

## 1. 원칙

| 원칙 | 이유 |
|------|------|
| **관계 = 데이터, 관계도 = 결과물** | 손으로 그린 관계도는 NPC가 50명만 넘어도 관리가 불가능하다. 데이터에서 자동 생성하면 항상 최신이다 |
| **관계는 방향이 있다** | A가 B를 사랑해도 B는 A를 모를 수 있다. 모든 관계는 `A → B` 로 따로 기록한다 |
| **사실과 인식을 분리한다** | "A가 B를 배신했다"(사실)와 "C는 그 사실을 안다"(인식)는 다른 데이터다. 비밀과 소문은 여기서 나온다 |
| **혈연은 한 번만 적는다** | 부모만 적으면 형제·사촌·조부모는 자동 계산. 중복 입력 = 모순의 원인 |
| **등급별로 깊이를 다르게** | 모든 NPC를 같은 깊이로 쓰면 영원히 못 끝낸다 (§2) |
| **검증은 기계가 한다** | 나이·생사·위치·혈연 모순은 검증 도구가 매번 잡는다 (§6) |

---

## 2. NPC 등급 — 깊이를 나눠서 관리한다

| 등급 | 수 (1.0 목표) | 작성 방식 | 관계 수 | 예 |
|------|---------------|-----------|---------|----|
| **S — 핵심** | 30~40 | 전부 손으로. 전용 대사·스토리렛·일정 | 10~25 | 용황 일가, 카스파르, 회색여울 핵심 인물 |
| **A — 주요** | 150~250 | 프로필 템플릿 + 손으로 쓴 비밀·목표 + LLM 초안 대사 | 5~12 | 각 지역의 영주, 길드장, 스승, 동료 후보 |
| **B — 보조** | 1,000~2,000 | 반자동 생성: 이름·종족·직업·성격·관계 3~6개 | 3~6 | 마을 주민, 상인, 경비, 노예 |
| **C — 익명 인구** | 수십만 (통계) | 정착지 통계만. 플레이어가 관심을 가지면 즉석 생성 → B로 **승격** | 0 | "배급 줄에 선 노인" |

- 승격 규칙: 플레이어와 3번 이상 의미 있는 상호작용 / 중요 사건에 연루 / 플레이어가 이름을 물어봄 → C→B. 
  B가 플레이어의 동료·적·연인이 되면 → A 수준 프로필을 LLM 초안 + 수정으로 보강.
- **회차 안의 가족·동료**: 주인공의 배우자·자녀·제자·핵심 동료는 자동으로 A 이상이 된다. 회귀하면 그 관계는 세계에서 사라지고 주인공의 기억에만 남는다 (12, 20 문서).

## 3. 관계 데이터 모델

### 3.1 관계의 종류 (6계열)

| 계열 | 유형 | 방향 | 예 |
|------|------|------|----|
| **혈연** | 부모, (자녀·형제·조부모는 자동 계산), 배우자, 사생아 | 사실 | 바르스카르 → 카스파르 : 아버지 |
| **위계** | 주인-소유물, 영주-가신, 감독-노예, 고용, 스승-제자, 교단 상하 | 사실 | 고드릭 → 마르타 : 주인 |
| **감정** | 호감, 신뢰, 두려움, 존경, 원한, 연모, 질투, 경멸 | 일방 | 오웬 → 사라 : 연모 70 |
| **거래** | 빚, 계약, 맹세, 뇌물, 협박 | 사실 | 하겐 → 볼크 : 탈주자 판매 거래 |
| **비밀** | X는 Y의 비밀 Z를 안다 | 인식 | 사라 → 고드릭 : "노예 중개인 거래"를 앎 |
| **조직** | 소속, 세포 연결, 밀정 | 사실(대개 비공개) | 레아 → 멜리산드 : 첩자 |

### 3.2 관계 기록 형식

```yaml
# content/base/relations/greyford.yaml
- from: npc_owen_raven
  to: npc_sara
  type: 연모
  values: { affection: 70, trust: 40, respect: 20 }
  since: AS 310
  public: false                 # 공개된 관계인가
  known_by: [npc_martha]         # 이 관계를 아는 사람 (공개면 생략)
  note: "남작의 아들이 인간 하녀를. 들키면 사라가 죽는다."
  hooks: [owen_sara_elope, martha_blackmail_owen]   # 이 관계가 여는 스토리렛

- from: npc_hagen
  to: npc_irma
  type: 원한의_원인            # 하겐이 이르마의 남편을 죽였다
  fact: fact_hagen_killed_irma_husband
  public: false
  known_by: [npc_fayne]         # 페인이 봤다
```

### 3.3 사실(Fact)과 인식(Knowledge)

```yaml
# content/base/facts/greyford.yaml
- id: fact_hagen_killed_irma_husband
  text: "하겐이 AS 310, 이르마의 남편 울프의 목을 졸라 여울강에 던졌다"
  truth: true
  known_by: [npc_hagen, npc_fayne]
  believed_false_by: { npc_irma: "탈주자 무리가 죽였다" }   # 잘못 믿는 사람
  danger: 4                    # 퍼지면 일어날 일의 크기
```

- 모든 **비밀·소문·협박·폭로** 스토리렛은 이 데이터를 조건으로 쓴다.
- 플레이어가 사실을 알게 되면 `known_by`에 추가 → 새 선택지(이르마에게 말한다 / 하겐을 협박한다 / 침묵한다).
- 소문 시스템(GAME_DESIGN §3.7)이 `known_by`를 시간에 따라 퍼뜨린다.

### 3.4 혈연과 가계도

```yaml
# content/base/lineages/raven.yaml
house: house_raven
members:
  - { id: npc_godric_raven, born: AS 172, parents: [npc_aldric_raven, npc_hilde_raven] }
  - { id: npc_owen_raven,   born: AS 272, parents: [npc_godric_raven, npc_rowena_raven], legit: true }
```
→ 형제·사촌·조카·상속 순위는 **자동 계산**. 가계도 그림도 자동 생성.

## 4. 관계도를 "보는" 방법 — 자동 생성되는 5가지 뷰

| 뷰 | 질문 | 형태 | 생성 방식 |
|----|------|------|-----------|
| **① 인물 중심 (자아망)** | "브람과 엮인 사람은?" | 한 인물 + 1~2단계 이웃 | 인터랙티브 뷰어 |
| **② 지역 관계도** | "회색여울은 어떻게 얽혀 있나?" | 지역 NPC 전체, 세력별 색 | Mermaid 자동 생성 → 문서에 삽입 |
| **③ 세력 관계도** | "용제국 내부 파벌은?" | 세력·가문 단위 노드 | Mermaid + 매트릭스 표 |
| **④ 가계도** | "레이번 가문 상속 순위는?" | 트리 | 혈연 데이터에서 자동 |
| **⑤ 비밀 지도** | "누가 누구의 약점을 쥐고 있나?" | 비밀·협박·빚 엣지만 | 인터랙티브 뷰어 필터 |

- **인터랙티브 뷰어** (`prototypes/relations/index.html`): 검색, 지역·세력·종족·관계 유형 필터, 인물 클릭 시 자아망 확대, 비밀 관계 표시 토글.
- **자동 문서** (`docs/world/relations/*.md`): 지역·세력별 Mermaid 관계도. `tools/build_relations.py`가 데이터에서 생성 — **절대 손으로 고치지 않는다.**
- 선 스타일 규칙: 혈연=굵은 실선, 위계=화살표, 감정 +=초록/−=빨강, 비밀=점선, 거래=쇄선.

## 5. 게임 안의 관계도 — "인물 수첩"

관계도는 개발 도구이면서 동시에 **게임 메커니즘**이다.

```
┌──────────────────────────────┐
│  인물 수첩 — 회색여울          │
│                                │
│   [브람] ──?── [북방 탈주자들]   │  ← 플레이어가 짐작만 하는 관계 (물음표)
│     │                          │
│   믿음                          │
│     │                          │
│   [엘사] ┄┄┄┄ [이름 없는 자들?]  │  ← 소문으로 들은 관계 (점선)
│                                │
│   [하겐] ━━━ [볼크] (거래)       │  ← 직접 목격한 관계 (실선)
│                                │
│  메모: "하겐을 믿지 마"          │
└──────────────────────────────┘
```

- 플레이어는 **자신이 아는 관계만** 본다 (`known_by`에 플레이어가 있는 것 + 관찰·소문으로 추정한 것).
- 관계에는 확신도가 있다: **목격(실선) / 소문(점선) / 추측(물음표)**. 소문은 틀릴 수 있다.
- 추리 게임처럼 관계를 이어 붙이며 음모를 파악하는 것이 재미의 한 축이 된다.
- 회귀하면 모든 NPC의 관계 수치는 회귀점 값으로 돌아간다. **인물 수첩은 남는다** — 다만 관계 수치 없이 사실·관찰만 (03 `Soul.notebook`). 지난 회차의 관계는 ◇ 표시(나만 기억하는 인연, 20 문서)로 보인다.

## 6. 검증 도구 — 모순은 기계가 잡는다

`tools/validate_world.py` (빌드할 때마다 실행)

| 검사 | 예 |
|------|----|
| 참조 무결성 | 관계·사실·스토리렛이 존재하지 않는 NPC id를 가리키는가 |
| 나이·혈연 | 부모가 자녀보다 종족별 최소 성숙 나이(인간 14, 용인 60, 엘다르 200…)만큼 나이가 많은가 |
| 생사 | 죽은 NPC가 현재 시점 관계(현재 연모, 현재 고용)를 가지는가 |
| 위치 | 같은 시각에 두 장소에 있는 일정이 있는가 |
| 위계 순환 | A가 B의 주인이고 B가 A의 주인인가 |
| 비밀 일관성 | 비밀을 아는 사람 목록에 그 비밀이 생기기 전에 죽은 사람이 있는가 |
| 정본 일치 | 정본 인물(WORLD_BIBLE)의 나이·종족·관계가 데이터와 같은가 |
| 고립 노드 | 관계가 하나도 없는 A등급 이상 NPC (이야기에 엮이지 않음) |
| 과밀 노드 | 관계가 40개 이상인 B등급 NPC (주인공화 — 등급 조정 필요) |

## 7. 수천 명의 관계를 "만드는" 방법

### 7.1 손으로: S·A등급 — "관계 씨앗"
작가는 이야기가 되는 관계만 쓴다: **사랑·원한·빚·비밀·배신·충성**. 한 NPC당 2~5개의 "갈등이 있는 관계"가 목표.

### 7.2 절차적으로: B등급 — 공동체 생성 규칙
정착지마다 규칙으로 관계망을 짠다:

```
가구 생성     → 가구당 2~6명, 혈연 자동
이웃          → 같은 구역 가구끼리 호감 −20~+40
직업망        → 같은 직업끼리 경쟁 or 협력, 상하 관계
빚            → 가난한 가구의 30%가 부유한 가구·감독관에게 빚
비밀          → 인구 10명당 비밀 1개 (불륜, 절도, 숨긴 탈주자, 숨긴 은화, 글을 앎)
원한          → 인구 20명당 원한 1쌍
밀고자        → 인간 마을 50명당 목줄단 협력자 1명 (정체는 비밀)
```
→ 그다음 LLM이 각 관계에 한 줄짜리 사연을 붙인다 (개발 단계, 05 문서 파이프라인).

### 7.3 시뮬레이션으로: 시간이 관계를 바꾼다
- 매주: 같은 장소·같은 일을 하는 NPC끼리 호감이 조금씩 움직인다.
- 사건: 배신·구조·죽음은 관계를 크게 바꾸고 새 원한을 만든다.
- 임계값: 원한 80 이상 → 복수 스토리렛 후보 / 연모 + 신분 차이 → 도주·발각 스토리렛 / 빚 + 흉년 → 매각·협박.
- 이렇게 **플레이어가 없는 사이에도** 관계망이 스스로 이야기를 만든다.

## 8. 작업 흐름 요약

```
CHARACTERS.md / HOUSES_AND_FACTIONS.md (사람이 읽는 설정)
        │  (추출: 에이전트·스크립트)
        ▼
content/base/npcs/*.yaml · relations/*.yaml · facts/*.yaml · lineages/*.yaml   ← 진짜 원본
        │
        ├─ tools/validate_world.py  → 모순 보고서
        ├─ tools/build_relations.py → docs/world/relations/*.md (Mermaid 관계도)
        │                           → prototypes/relations/ (인터랙티브 뷰어)
        └─ 게임 엔진                 → 대사 조건 · 스토리렛 조건 · 소문 전파 · 인물 수첩
```

> 설정 문서가 커지면 **원본을 데이터로 옮기고, 문서는 데이터에서 생성**하는 방향으로 전환한다.
> 그 시점부터 NPC 추가는 "YAML에 한 명 추가 → 빌드" 가 된다.
